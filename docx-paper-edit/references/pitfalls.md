# 论文 docx XML 手术踩坑清单（实测教训）

本清单来自软件学报两篇论文（RSSM+CROWN 29 条文献、FMV 世界模型 44 条文献）多轮编辑的实测经验。
环境背景：本机标准 Python 的 Lib 损坏、auto_LiRPA 不兼容 → **一切 docx 操作走 Node.js**；
PowerShell stdout 不回显但文件操作有效；Glob 对中文路径可能返回空 → 用 `ls`/`Get-ChildItem`。

## 一、解包与重打包

- **解包**：Git Bash `unzip -o file.docx -d dir`。返回码 1 通常只是警告（时间戳/额外字段），
  以 `dir/word/document.xml` 存在与否为准，不要因返回码误判失败。
- **重打包**：本机无 `zip`/`xmllint`。用 PowerShell `Compress-Archive`——
  **它要求 `.zip` 后缀**，先压缩成 `.zip` 再 `Move-Item` 改名为 `.docx`；
  `-Path` 用 `目录\*`（注意通配符，否则会把目录本身压进去）。
- **必须先备份**：改前 `cp 原.docx 原.docx.<标记>.bak`。交付覆盖后对**交付文件**重新解包复检。

## 二、引用扫描（最易踩坑处）

- 正文引用有**四种形态**，扫描正则必须全覆盖，否则首现顺序算错、误判"未引用"：
  1. 单条上标 `[n]`（独立 `<w:t>` run）；
  2. 相邻簇 `[n][m][k]`（同一个 `<w:t>` 内连续括号）；
  3. 合并式 `[n,m]`（中文全角逗号也要兼容）；
  4. **区间式 `[a−b]`，连接符是 U+2212（−）不是 ASCII 连字符**。
- **数学区间排除**：`[−1,1]`（zonotope 生成元）、`[0,1]`（归一化区间）、`[-1,1]`（ASCII 负号）
  会伪装成引用。判定规则：括号内**全部**数字 ∈ 1..N **且** 不含负号前缀/含 0 才算引用；
  保险做法是先全量扫描一遍所有含数字的括号组、人工过目分类后再跑重排。
- 引用编号可能**内联在正文文本中**（如 "Parmar[29] 进一步…"、"文献[8]"），不全是上标 run，
  扫描 `<w:t>` 内容即可，但**不要**扫 `m:t`（OMML 公式文本）里的方括号。
- 参考文献列表的定位：找第一个 `<w:t>` 内容匹配 `^\[1\] `（后跟非数字）。注意有的文档
  英文列表**没有"参考文献"标题**、且位于"附中文参考文献"标题**之前**，用 `indexOf("参考文献")`
  找列表起点会失败。

## 三、编号重排

- 映射规则：正文首次出现顺序 → 新编号 1..N；**同一引用组内按升序计入首现**；
  合并式/区间式组映射后仍连续则保留 `[a−b]`，否则退化为逗号式 `[a,b,c]`。
- 相邻括号簇（同一 `<w:t>` 内无间隔）映射后**簇内升序重渲染**（如旧 `[18][19][16]`→`[11][12][13]`）；
  跨 run 的簇不做合并（格式风险大，可接受）。
- 文献列表重排按**段落粒度**：strip 后 `^\[(\d+)\]\s` 判定条目段落；新 i 号 = 旧 order[i-1]
  条目改前导编号后按 1..N 顺序替换到原条目位置；**非条目段落（作者简介、空段）原位保留**。
- **附录联动**：中文期刊的"附中文参考文献"附录条目前导编号与主列表一一对应，
  必须同步改号并按新号升序重排，否则附录对应关系断裂。
- **no-op 校验陷阱**：用 `改前===改后` 判断"改号是否生效"会在恒等映射（old1→new1、old2→new2…）时
  误报失败。正确做法：改号后重新提取前导编号，验证它等于目标值。

## 四、正文 XML 精确编辑（替换文献/新增引用/改写短语）

- 每处修改强制 **exactly-one 匹配**（`indexOf` 找到后确认 `indexOf` 第二次不再出现），
  找不到或匹配多处一律报错退出，绝不模糊替换。
- **拆 run 插入的闭合陷阱**：把一个 `<w:t>原文</w:t></w:r>` 在中点拆开插入新内容时，
  新内容写成 `<w:r><w:rPr>…</w:rPr><w:t xml:space="preserve">新文本`（**不闭合**），
  由原收尾 `</w:t></w:r>` 收尾；若新串自己闭合，原收尾标签就变孤儿，导致标签不平衡。
  靠"改后统计 `<w:p>`/`<w:r>`/`<w:t>` 开闭数相等"检查抓此类错误。
- 上标引用 run 模板（正文）：
  `<w:r><w:rPr><w:rFonts w:hint="eastAsia" w:ascii="Times New Roman" w:hAnsi="Times New Roman" w:eastAsia="宋体"/><w:b w:val="0"/><w:i w:val="0"/><w:sz w:val="21"/><w:vertAlign w:val="superscript"/></w:rPr><w:t xml:space="preserve">[n]</w:t></w:r>`
  （字号 21=10.5pt；RSSM 文献列表用 sz=15，FMV 用 15/21，**以目标文档既有条目实测为准**，勿照抄）。
- 参考文献条目段落模板：复用相邻条目段落的 `<w:pPr>`（含 hanging indent），正文 run 用
  `<w:sz w:val="15"/>` 或实测值。
- 引用编号与条目文本常分属不同 run，**跨 run 的连续字符串搜不到**——跨版本核验时先
  strip 标签再搜纯文本。

## 五、校验三层（缺一不可）

1. **改后自校验**：标签平衡、首现序列==1..N 严格单调、列表 1..N 有序、附录升序、无悬空。
2. **跨版本内容等价**：新列表第 k 条的文本内容 == 旧列表第 order[k-1] 条（逐条 strip 比对），
   证明"只动编号、不动内容"。
3. **交付复检**：重打包覆盖后，对**交付的 docx** 重新解包跑一遍全部核验（ZIP 完整性 + 核验脚本）。

## 六、其他

- PowerShell 大量输出（进度条）会刷屏但无害；`echo $?`/退出码为准。
- 批量 sed 改自己的脚本前先确认转义；内联 `node -e '…'` 含单引号/`$` 时容易被 shell 截断，
  复杂脚本一律写文件再执行。
- 文献真实出处核实（新增引用前）：逐条 Web 检索确认作者/ venue/ 年份/ DOI；
  招聘广告、研讨会非审稿报告要向用户说明层级差异。
- GB/T 7714 顺序编码制要求：首现顺序单调、列表有序、无悬空、无未引用条目；
  知网查重按**连续 13 字**标红——同一作者两篇投稿互查也要做。
