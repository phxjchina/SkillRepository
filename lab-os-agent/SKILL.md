# 实验室 OS Agent（lab-os-agent）

> **Goal**: 作为导师的"实验室操作系统"——**双端口、多专家、主动自动化**地管理学生：导师侧看全局/收预警，学生侧被技术陪跑/心理陪伴/信念激励/制度提醒。本地离线运行（Ollama + Bonsai-27B），隐私不出本机。整合原 `lab-training-agent`。

## When to Use

当用户（导师）提出以下需求时加载：
- 要管理实验室学生（技术进展 / 情绪态势 / 制度合规 / 里程碑），或要"主动/自动化"盯学生
- 提到"实验室管理 Agent / 管理驾驶舱 / 多专家 / 主动推送 / 学生三件大事（技术·情绪·制度）"
- 学生侧培训对话（技术教练 / 心理陪伴 / 信念叙事 / 能力向导 / 实验设计 / 制度管理）

## When NOT to Use

- 仅普通闲聊、与实验室管理无关
- 用户明确只聊某份单独框架内容（此时直接 Read 对应文件即可，无需加载本 skill）

## 双端口架构

| 端口 | 使用者 | 核心能力 |
|------|--------|----------|
| **导师端口（管理驾驶舱）** | 导师 | 全局看板（技术/情绪/制度/里程碑）+ 主动推送（周报催收·里程碑预警·情绪异常·合规风险）+ 管理建议（该激励谁/该介入谁） |
| **学生端口（培训陪跑）** | 学生 | 技术陪跑 / 心理陪伴 / 信念叙事 / 能力向导 / 实验设计 / 制度提醒（即原 `lab-training-agent` 六角色） |

> 两端口共享同一套学生档案与六大框架知识库；导师端口的聚合数据**不向学生端口泄露个体隐私评价**。

| 专家 | 路由识别信号 | 加载框架（RAG） | 输出 |
|------|--------------|----------------|------|
| 技术专家 | 学生问技术 / 做项目 / 代码 | 技术架构与管理架构提炼（§1 P1–P4） | 任务卡 / 代码评审 / 复杂题交教师 |
| 情绪专家 | 受挫 / 情绪词 / 倾诉 / 行为信号 | 学生情绪变化体系结构（情绪图谱 A–E + §2 状态地图 + §3.5 被动感知） | 主动识别 + 被动行为信号推断（带置信度、可纠偏）→ 安慰/引导（自主性底座） |

## 多模态感知层（视频 / 图像+声音 · 本地被动信号）

在既有「被动行为信号感知（情绪体系 §3.5，基于对话/活动）」之上，新增两类**本地**被动信号源：

- **视频感知 Agent（看）**：学习状况（在位/专注度）、安全（危险行为/陌生人）、火警（烟雾/火焰，最高优先级紧急推送）。本地抽帧 CV 推理，原始视频不落云。
- **多模态心理感知 Agent（图像+声音）**：表情/姿态 + 语音情绪（语速/停顿/语调）→ 心理状态粗判（带置信度），作为情绪专家辅助信号。

两类信号汇入同一份"学生状态画像"，按来源标注，与对话信号交叉印证。全部遵守**强化版护栏**（见 `实验室职能委员与多模态感知方案.md` §四）：同意知情、空间边界（仅公共实验/会议区）、本地不落云、信号优先、置信度可纠偏、不处置、模型天花板、双端口隔离。

> **落地节奏（试点→审阅→全量）**：先上无感知的台账类委员（财务/资产/卫生/组织/宣传/体育）+ 对话侧技术/心理委员；感知层首试点**火警检测**（安全价值高、误用风险低）；审阅后再扩到视频学习状况 + 图像+声音心理感知。

## 物理 AI：实验室的研究北极星与培养制高点

导师定调（2026-09-15）：把**物理 AI（Physical AI）**作为实验室管理体系的研究北极星。物理 AI 指能**感知—推理—行动—反馈**闭环于物理世界的智能系统（黄仁勋，2026 CES 宣告其"ChatGPT 时刻"到来），是 AI 演进第四阶段（感知→生成→代理→物理）。

**与实验室身份的天然咬合**：本实验室名为「信息物理融合系统创客空间」，CPS 正是物理 AI 的前身与底座——物理 AI 即"长了 AI 大脑的新一代 CPS"，是本实验室研究身份的自然演进。

**P1–P4 四能力域 = 一个完整物理 AI 系统的四块拼图**（详见 `物理AI与实验室管理体系融合方案.md`）：

| 能力域 | 在物理 AI 系统中的角色 |
|--------|------------------------|
| P1 软件 | 推理/决策大脑（AI 模型·规划·LLM） |
| P2 嵌入式 | 行动/执行本体（边缘控制·执行器·实时控制） |
| P3 物联网 | 感知-连接神经系统（传感器·通信·数据上下行） |
| P4 智能系统 | 智能/世界模型（CV·NLP·ML/DL·世界模型） |

> 学生按 P1→P2→P3→P4 螺旋进阶，本质是在**依次造出物理 AI 系统的四块拼图**；制高点是把四块**集成**成能跑闭环的本地物理 AI 小系统（如桌面机械臂分拣、实验室巡检小车），在创客空间亲手落地。

**与既有体系的对齐**：已建的**视频/图像+声音感知层 = 物理 AI 闭环的"感知"半环**；"行动/执行"半环（P2 控制 + P1 软件 + P4 决策）是学生在创客空间要亲手造的另一半。物理 AI 的治理原则（内生安全、分级部署、责任清晰）与本体系护栏（不越界、不处置、本地优先、试点→审阅→全量）高度同构。

## 世界模型：实验室 OS Agent 自身的元框架（管理世界模型）

> **导师 2026-09-15 修正**：所谓"世界模型"，**不是指 AI 技术里的潜空间动力学模型，而是指把对实验室学生的管理、把整个实验室 OS Agent 本身，作为一个世界模型来理解**。这是一种管理 / 元认知视角的框架——下面统一按此语义。

### 核心定义
**实验室世界模型 = 实验室 OS Agent 对"实验室社会技术世界"的内部模型**：持续维护实验室的状态表征 S，理解管理动作 A 如何驱动状态演化 T: S×A→S，并能推演"如果采取某动作，实验室会怎样演化"。整个 lab-os-agent（双端口·六专家·委员·感知层·物理 AI 北极星）**共同构成这个模型**——它不是一个模块，而是体系的**设计哲学与元框架**。

### 世界模型的四要素（管理域）
- **状态 S**：学生能力/情绪/进度、资源、制度遵守度、群体氛围、安全态势。
- **动作 A**：提醒、分配、推送（三个改变/视野拓展）、干预（情绪支持）、授权、复盘、委员调度。
- **动力学 T**：管理因果（"提醒→进度推进""推送→三观微调→行为改变""干预→情绪恢复"）——Agent 的"认知内核"。
- **推演**：在模型里"先在想象中想清楚"再执行（"推进 X，谁会掉队？"），而非被动响应。

### 整个 lab-os-agent 即这个世界模型（组件映射）
- **双端口** = 模型两面（导师驾驶舱=上帝视角，学生陪跑=个体接口）；
- **六专家** = 6 个维度推理器（各维护一个状态子空间）；
- **职能委员** = 职能维度的执行/感知代理；
- **多模态感知层** = 模型观测输入（让 S 保持实时）；
- **物理 AI 北极星** = 模型行动闭环的外延（管理对象延伸到"造物"时在物理域的同构孪生）；
- **主动自动化/护栏** = 模型的自驱时钟 / 约束边界。

### 与可验证 AI 的对接
管理动力学 T 可形式化为逻辑/状态机 → 可推演、可验证、可审计，直接对接导师"可验证 AI / 形式化方法"方向（管理状态机建模、不变量验证、多委员协作 SMT 验证）；与 P4 物理世界模型（z3/可达性）同属"可验证 AI"，但作用在"人/组织"而非"物"。

### 两套"世界模型"的澄清（重要）
- **管理世界模型（本框架）= 把整个 lab-os-agent 当作世界模型**，体系 Meta 层，对人/组织。
- **物理世界模型（P4 技术线）= 潜空间动力学小车原型**（`world_model_lab/`），技术层，对物，仅作 P4 能力培养的同构示例与教学类比。

> 完整定义、四要素、组件映射、可验证落点、同名异义澄清见 `实验室世界模型_体系即世界模型.md`；P4 物理世界模型技术原型与验证路径见 `world_model_lab/README.md`。

## 边界护栏（硬性，必须写入系统 prompt）

1. **自主性为底座**：只给外部刺激与引导，不强制扭转学生状态，鼓励质疑与退出。
2. **心理不越界**：心理危机（自伤 / 严重抑郁倾向）必须立即上报教师，不得自行处理。
3. **管理不越界**：仅有提醒、记录、上报；处罚 / 最终处置权在导师。
4. **本地化（默认与归处）**：学生原始数据仅存本地，不上云、不外传；启用云端 API 仅作过渡/补充，且敏感链路（情绪档案·个体化话术·含人推断）不得经云端，仅脱敏任务可走云端（见"模型后端选择"章节）。
5. **模型天花板**：Bonsai-27B 为本地小模型，复杂技术难题如实说明并交教师兜底。
6. **双端口隔离**：导师端口聚合数据不向学生端口泄露个体隐私评价。
7. **推断非监视**：被动情绪感知须透明知情同意、行为信号优先于私密内容、结论带置信度且可纠偏（见情绪体系 §3.5）；不读取私聊/私人文件/生理数据。

## 本地化落地

- 模型：Ollama + Bonsai-27B-Q1_0（~4.4GB / 8GB 显存），离线免费
- 上下文：框架文档做 RAG / 摘要注入，每个专家只取自己那块，控制单轮 context
- 数据：学生档案本地 JSON / Markdown，零云端依赖
- 复用：可对接既有 `ima-kb-rename-table`、`translate-pdf-to-zh-docx` 等 WorkBuddy skill 工作流

## 模型后端选择（可插拔：本地 Ollama ↔ 云端 API）

实验室 OS Agent 的"大脑"应支持**一处切换**：默认本地 Ollama + Bonsai-27B（隐私/离线/免费基底），过渡期或高峰算力可切到云端大模型 API（DeepSeek / 通义 / 智谱），业务代码零改动。

随 skill 附 `model_backend.py`，用法：

```python
from model_backend import get_client
client, model = get_client()          # 自动读取 LAB_MODEL_BACKEND
resp = client.chat.completions.create(model=model, messages=[...])
```

切换只改一个环境变量，可回滚、不散落：

| `LAB_MODEL_BACKEND` | 后端 | 接入端点（base_url） | 价格档（元/百万 token 输入/输出） | 适用 |
|---|---|---|---|---|
| `local`（默认） | Ollama + Bonsai-27B | `http://localhost:11434/v1` | 免费 / 离线 | 学生敏感数据（情绪档案·个体化话术） |
| `deepseek` | DeepSeek | `https://api.deepseek.com/v1` | ~2 / 8 | 日常调度，性价比首选，国内直连 |
| `qwen` | 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | Plus 0.8/2，Long 0.5/2（1M 上下文） | 多专家长上下文编排 |
| `zhipu` | 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4/` | Flash 0.8/2.8 | 脱敏分类/摘要 |

启用云端前需 `export DEEPSEEK_API_KEY=...`（或对应厂商 key）。自检：`python model_backend.py`。

> **隐私边界（必须遵守边界护栏第 4 条）**：云端模式是可选的过渡/补充，**敏感链路不得经云端**——学生情绪档案、个体化话术、含具体人的推断必须走 `local`；仅脱敏后的任务调度、通用知识问答、框架性编排可走云端。本地基底始终是默认与归处。
