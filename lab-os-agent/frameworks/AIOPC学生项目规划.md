### 优先级覆盖判读
- **P1 软件系统**：13 个产品**全部**以 P1 软件外壳为底座（Web / 后端 / UI / 工作流），是学生的统一入口——先跑通外壳即建立"我能做出来"的成就感。
- **P4 智能系统**：11 个产品以 LLM / RAG / CV / 知识图谱 / 运筹为 AI 内核，是学 AI 方向学生的**主战场**。
- **P2 嵌入式**：仅 #11 无感打卡强依赖（蓝牙 Beacon / 声纹硬件），属进阶拓展项。
- **P3 物联网**：本产品池**暂无强依赖**，后续可拓展"设备联动 + 端云协同"类（如智能家居中控）作为 P3 专项。

## 二、对"学人工智能方向学生"的优先级解读

> 核心逻辑：P1 软件 = 把产品**跑起来**的工程外壳；P4 智能系统 = 产品的**AI 内核**。二者构成"先建立成就感、再攻坚硬核"的天然进阶。

1. **入门（大一–大二）**：用 P1 软件能力把某产品的最小可用外壳做出来（如 #9 生活 OS 的待办+日历，或 #1 实验室智能体的角色看板），快速验证"我能交付"。
2. **深化（大二下–大三）**：在 P1 外壳内嵌入 P4 AI 内核（LLM Agent / RAG / 知识图谱），让产品从"能点"变"懂行"。
3. **攻坚（大三–大四）**：选 #11（P2 硬件）、#13（P4 运筹）、#8/#12（P4 知识图谱/CV）等高难项做产品级交付，对接毕设与竞赛。

与"自主性底座 + 三个改变"自洽：先让 P1 小产品跑通制造正向情绪（情绪图谱的"沉浸安定/确定理解"），再逐级加难避免"动力缺失/无动机"。

## 三、MVP 建议（沿用彭老师"1–2 个高校类先跑通"）

| 优先级 | 产品 | 理由 |
|--------|------|------|
| **首选 MVP** | #1 实验室管理智能体（学生版） | ① 最贴近彭老师自身资源，需求零成本获取；② **可直接复用前面已建的《实验室全能培训 Agent》框架**，形成"框架→产品"闭环；③ 纯 P1+P4，本地 Ollama+Bonsai 即可跑，隐私不出本机 |
| **次选 MVP** | #2 毕设指导教师辅助智能体 | 痛点刚性（流程易错漏）、RAG+规则校验技术成熟，同样贴近高校场景 |
| 暂缓 | #4 督导 Agent | 需求待 QQ 定，先不排 |

> 建议同一批学生按 #1 起步，跑通"P1 外壳 + 基础 P4 Agent"后再扩张到 #2，形成高校教师 AI 工具箱产品线（原规划 A 类 1–4 打包）。

## 四、产品 → 任务卡拆解模板（以 #1 实验室管理智能体·学生版为例）

```
【产品】实验室管理智能体（学生版）
【P1 外壳任务】
  - 角色看板：CEO/CTO/PM/QA/经纪人 五类虚拟角色卡片 + 责任区
  - SOP 表单：周报 / 交接 / 考勤 三类流程的 Web 录入与状态流转
  - 技术栈：Python(FastAPI) + 前端(Streamlit/React) + 本地 JSON 存储
【P4 内核任务】
  - LLM Agent：按角色扮演，自动生成周报摘要 / 交接清单初稿
  - RAG：检索《实验室制度》注入上下文，回答"某流程该怎么做"
  - 技术栈：Ollama + Bonsai-27B + 框架文档向量化
【训练四阶段】启蒙(看框架)→训练(做 P1 外壳)→产出(接 P4 内核)→闭环(试点 3–5 人)
【三个改变锚点】改变自己=工程力提升；改变环境=实验室 SOP 固化；改变世界=(远期)产品化外售
【本地化约束】全部跑本地，数据不出本机
```

> 同一模板可套用到全部 13 个产品：先拆 P1 外壳，再填 P4 内核，最后挂训练阶段与三个改变。
