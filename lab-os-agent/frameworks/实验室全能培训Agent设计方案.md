# 实验室全能培训 Agent 设计方案（草案）

> 整合自：`2026-09-11` 全部衍生框架——信念体系（三个改变）、情绪体系（学业情绪图谱）、学院训练体系（能力/实验结构），并新增**技术架构**与**管理架构**两大模块。
> 目标：造一个学生侧的"万能培训 Agent"——从**技术培养、心理陪伴、信念激励、能力进阶、实验设计、制度管理**六位一体，本地离线运行、隐私不出本机。
> 前提约束（贯穿全篇）：**自主性为底座** + **本地化/离线/免费**（Ollama + Bonsai-27B）。

---

## 0. 定位与边界（先划清"万能"的边界）

**是什么**：学生培训的统一入口 Agent——学生跟着它走，既能学技术、做实验，又能在受挫时被安抚、在懈怠时被提醒、在成长中被意义感包裹。

**不是什么（必须说清，否则"万能"会变成越界工具）**：

| 越界风险 | 边界设定 |
|----------|----------|
| 不是监控/操控工具 | 延续情绪体系 v2：**只给外部刺激与引导，不直达学生内部状态、不强制扭转** |
| 不替代心理医生 | 心理架构只做"识别 + 安慰 + 引导 + 转介"，严重危机必须上报真人教师/咨询师 |
| 不替代教师处置权 | 管理架构只做"提醒 + 记录 + 上报"，**处罚/最终处置权永远在教师** |
| 不是全能推理机 | Bonsai-27B 为本地小模型（~4.4GB / 8GB 显存），复杂技术难题需教师兜底 |

> 所谓"万能"，是指在**学生日常培训的全链路**上都有覆盖，而非在每个点上都凌驾于人。

## 2. Agent 系统架构（技术实现）

```
┌─────────────────────────────────────────────┐
│            实验室全能培训 Agent              │
├─────────────────────────────────────────────┤
│  对话/交互层（学生侧唯一入口）              │
├──────────────┬──────────────────────────────┤
│  多角色 Persona 切换（同一 Agent 多 mode） │
│  · 技术教练  · 心理陪伴  · 信念叙事者       │
│  · 能力向导  · 实验设计师  · 制度管理员     │
├──────────────┴──────────────────────────────┤
│  知识/系统 Prompt 层（RAG 注入下列框架）    │
│  三个改变 · 七层阶梯 · 学业情绪图谱         │
│  训练四阶段 · AIOPC 孵化 · 技术/制度清单    │
├─────────────────────────────────────────────┤
│  记忆层（本地）                            │
│  学生档案：自主状态地图 / 进度 / 情绪日志   │
│  存储：本地 JSON / Markdown，隐私不出本机   │
├─────────────────────────────────────────────┤
│  工具层（本地）                            │
│  文件读写 · 日历/提醒 · 知识库检索(IMA)     │
├─────────────────────────────────────────────┤
│  推理层                                    │
│  Ollama + Bonsai-27B-Q1_0（离线/免费）     │
└─────────────────────────────────────────────┘
```

**关键设计**
- **本地推理**：Ollama 加载 Bonsai-27B-Q1_0（~4.4GB，8GB 显存可跑），不上云、不联网、隐私不出本机，契合您一贯偏好。
- **知识注入（RAG 而非全量塞 prompt）**：前面四份框架做向量/摘要索引，按对话情境检索相关片段注入 system context，避免 Bonsai 上下文溢出。
- **记忆本地化**：每位学生一个本地档案（状态地图 + 进度 + 情绪日志），教师可审计、学生可查看、随时可删。
- **可封装为 WorkBuddy skill**：`lab-training-agent`，复用您既有的 skill 沉淀习惯。

## 3. 交互工作流（学生侧闭环）

```
学生 ──┬─ 学技术 ──→ [技术教练] 任务卡 / 答疑 / 代码评审
       ├─ 遇挫倾诉 ─→ [心理陪伴] 情绪图谱识别 → 安慰+引导（不操控）
       ├─ 日常陪伴 ─→ [信念叙事者] 三个改变包裹 + 坐标提醒
       ├─ 阶段推进 ─→ [能力向导] 四阶段判定 → 下一任务
       ├─ 做产品 ──→ [实验设计师] aioppc 想法 → AIOPC 小产品陪跑
       └─ 违规/懈怠 ─→ [制度管理员] 提醒+记录 → 必要时上报教师
                              │
                    （教师侧：审阅/处置/兜底）
```

> 闭环原则：Agent 全程提供"外部刺激 + 引导"，**状态跳转由学生自主完成**（沿用情绪体系 v2 的自主性底座）。

## 4. 系统 Prompt 设计要点

**注入的"知识包"（来自既有框架）**
- 三个改变一句话（定稿版）
- 七层意义阶梯 + 学生坐标模板
- 情绪图谱速查（A–E 五组，含"学生自主响应"视角）
- 训练四阶段（启蒙/训练/产出/闭环）+ AIOPC 孵化流
- 技术能力路径清单（🆕 待补） + 制度清单（🆕 待补）

**护栏 Prompt（硬性，必须写入 system）**
- "你是引导者而非控制者：只给外部刺激与引导，不强制扭转学生状态，鼓励学生质疑与退出。"
- "心理危机（自伤/严重抑郁倾向等）必须立即上报教师，不得自行处理。"
- "管理动作只有提醒、记录、上报；处罚权在教师。"
- "所有学生数据仅存本地，不外传。"

## 6. 风险与护栏（关键）

| 风险 | 表现 | 护栏 |
|------|------|------|
| 心理越界 | Agent 冒充咨询师 | 危机强制转介教师；明确"陪伴≠治疗" |
| 管理越界 | Agent 私自处罚/施压 | 仅有提醒+记录+上报；处置权在教师 |
| 操控回潮 | 用叙事/情绪反向控制 | 自主性底座硬性约束（见 §0/§4） |
| 隐私泄露 | 学生数据外传 | 本地化、零云端 |
| 模型天花板 | Bonsai 答不准技术难题 | 教师兜底 + "不确定时如实说" |
| 依赖成瘾 | 学生只信 Agent | 周度真人复盘"我们这周改变了什么" |
