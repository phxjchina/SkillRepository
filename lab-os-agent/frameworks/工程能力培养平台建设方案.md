# 工程能力培养平台建设方案（技术体系总纲）

> 定位：**实验室 OS 技术体系的目标层与总纲**。以彭老师 2026-09-13 提供的建设目标为蓝本，给出培养体系结构、培养方式、考核指标，并与既有 **P1–P4 技术优先级**、**AIOPC 孵化**、**信念/情绪体系**对接。
> 与既有文件的关系：本文件是"为什么培养 / 培养成什么样"的目标层；`技术架构与管理架构提炼.md` 是"按什么路径培养"（P1–P4 能力域与年级螺旋）；`学院学生训练体系方案.md` 是"用什么叙事与孵化机制驱动"（AIOPC + 三个改变）；`实验室OS_Agent架构方案.md` 是"用什么系统执行"。四者构成完整技术体系。

---

## 1. 建设目标（彭老师蓝本 · 2026-09-13，忠实收录并理顺）

### 1.1 专业基础
以 **计算机科学与技术、软件工程、物联网工程、人工智能及自动化** 等专业的建设经验为基础。

### 1.2 目标系统
以开发四类智能系统为目标：

| 目标系统 | 典型形态 |
|----------|----------|
| 智能信息处理系统 | Web / 移动 / 小程序 / 数据平台 |
| 智能嵌入式系统 | 单片机 / STM32 / 边缘设备 |
| 智能物联网系统 | 端–云–端全链路（MQTT / 网关 / 平台） |
| 智能控制系统 | AI 算法驱动的感知–决策–执行闭环 |

> 终极培养目标：**培养学生综合运用所学知识，解决复杂工程问题的能力**。

### 1.3 能力目标切分（四子能力）
将能力目标切分为四类子能力：

- **信息系统开发能力**
- **嵌入式系统开发能力**
- **信息物理融合能力**（CPS，Cyber-Physical Systems）
- **人工智能算法及模型开发能力**

> 四类子能力相互组合，即可完成各类智能系统的开发——这正是**智能科学与技术专业的核心能力目标**。（彭老师原稿在此处表述重复啰嗦，已理顺。）

### 1.4 平台对内：融合需求、产出成果（解决毕设问题）
平台向内（校内）**融合**：

- 学生学习需求、就业需求、竞赛需求、实践需求；
- 老师在科研与竞赛方面的用人需求。

**产出**：竞赛成果、科研成果（论文 / 专利等）；同时**解决毕业设计准备不足、质量差的问题**。

### 1.5 平台对外：输送准工程师（解决就业问题）
平台向校外提供 **符合企业用人需求、具备各方面工程能力的准工程师**；**解决学生就业率低、就业质量差的问题**。

> 对内解决"培养质量（毕设）"，对外解决"培养出口（就业）"——一进一出，构成平台的价值闭环。

## 2. 与 P1–P4 技术优先级的映射（对接 `技术架构与管理架构提炼.md` §1.0/§1.1）

四子能力即 P1–P4 能力域的"能力目标"表述；P1–P4 是按由易到难编排的**落地路径**。

| 子能力（能力目标） | 对应 P 级 | 对应专业 | 目标系统 | 由易到难理由 |
|--------------------|-----------|----------|----------|--------------|
| 信息系统开发能力 | **P1** 信息处理系统 | 软件工程 | 智能信息处理系统 | 纯软、零硬件、反馈最快 |
| 嵌入式系统开发能力 | **P2** 嵌入式 | 计算机科学与技术 | 智能嵌入式系统 | 引入软硬结合 |
| 信息物理融合能力 | **P3** 物联网 | 物联网工程 | 智能物联网系统 | 叠加网络/云端/端到端 |
| AI 算法及模型开发能力 | **P4** 智能系统 | 智能科学与技术 | 智能控制系统 | 数学+ML/DL，抽象与算力最高 |

> 四子能力组合 = 各类智能系统 = 智能科学与技术专业核心能力（闭环呼应 §1.3）。Agent 据此把 P1 作为零基础学生默认起点，P4 作为高阶跃迁目标。

## 3. 培养体系结构（四维度叠加）

| 维度 | 结构 | 说明 | 对接 |
|------|------|------|------|
| **能力维度** | 四子能力（§1.3） | 横向能力面 | 本节 §1.3 |
| **年级维度** | 大一认知 → 大二功能 → 大三系统 → 大四产品（螺旋上升） | 纵向难度轴 | 技术提炼 §1.2 |
| **模块维度** | 每个模块 基础 → 进阶 → 应用 → 实战 | 模块内递进 | 技术提炼 §1.1 |
| **出口维度** | 竞赛 / 科研 / 毕设 / 就业 四出口 | 成果分流 | 本节 §1.4 / §1.5 |

> 四维度正交叠加：一个学生 = 处于某年级 × 修某模块 × 练某子能力 × 走向某出口。Agent 的"能力向导"据此定位其坐标并推送下一项任务。

## 4. 培养方式

- **项目驱动（最小单元 = aioppc 小产品）**：延续 `AIOPC学生项目规划.md` 孵化思路，把每个模块知识点打散为可交付小产品（如微信小程序、智能采集设备、NLP 小工具）。
- **老带新 + 四级梯队**：大四总控 → 大三中坚 → 大二执行 → 大一储备（对接管理架构 §2.3）。
- **竞赛 / 科研双轨**：竞赛成果 + 论文 / 专利，对应 §1.4 对内产出。
- **本地 AI 链路辅助**：用 Ollama + Bonsai-27B 跑开发辅助，**隐私不出本机、免费**，与一贯本地化偏好一致。
- **Agent 协作**：见 §6。

---

## 5. 考核指标

分三类，分别对应 §1.4（对内产出）与 §1.5（对外出口）的破题点：

| 类别 | 指标 | 对应破题 |
|------|------|----------|
| **过程指标** | 模块完成度、里程碑达成率、周报 / 代码仓库质量 | 对应 8 学期流程考核 |
| **成果指标** | 竞赛获奖数 / 级别、论文 / 专利数、毕设优秀率 / 盲审通过率 | 破"毕设准备不足、质量差"（§1.4） |
| **出口指标** | 就业率、就业质量（对口率 / 起薪 / 企业评价）、准工程师达标率 | 破"就业率低、质量差"（§1.5） |

> 指标设计原则：成果指标直接度量"对内产出"，出口指标直接度量"对外输送"——使平台建设目标可量化、可审阅（呼应"试点 → 审阅 → 全量"节奏）。

## 8. 附录：四子能力 × 年级 能力矩阵（目标水平）

> 用于能力向导判短板时的「目标锚点」：一个学生 = 处于某年级阶段 × 修某子能力。下表给出每个子能力在各年级阶段的**目标达成水平**（0 未触及 → 4 精通），Agent 据此对照学生现状指出缺口。

### 8.1 矩阵表（行=四子能力 / 列=年级阶段）

| 四子能力（P 级） | 大一·认知 | 大二·功能 | 大三·系统 | 大四·产品 |
|------------------|-----------|-----------|-----------|-----------|
| 信息系统开发能力（P1） | 1 入门：能写基础程序/小网页 | 2 基础：独立做 Web/小程序模块 | 3 进阶：搭数据平台/前后端 | 4 熟练：主导智能信息处理系统 |
| 嵌入式系统开发能力（P2） | —（建议大二引入） | 1 入门：点亮外设/读传感器 | 2 基础：STM32 小系统 | 3 进阶：边缘 AI/实时控制 |
| 信息物理融合能力（P3） | — | — | 1 入门：MQTT 上云/端到端 | 2 基础：物联网系统整合 |
| AI 算法及模型开发能力（P4） | — | — | 1 入门：调通经典模型 | 2 基础：自训/微调模型驱动控制 |

> **准工程师出口轮廓（大四应达成）**：P1 熟练(4) + P2 进阶(3) + P3 基础(2) + P4 基础(2)；四者组合即可开发各类智能系统（呼应 §1.3 / §1.5）。

### 8.3 与能力向导分支的对接

- `agent_adapter.py` 的能力向导在命中「短板 / 评估能力 / 四子能力」等意图时，会把上表四子能力结构注入 system，并（若配置了 `STUDENT_PROFILE_DIR`）读取该生档案的 `priority_path / current_P / completed_modules / stage` 作为背景，对照目标水平指出最薄弱子能力、给 P1→P4 补强路径。
- 未配置档案目录时，向导退化为「自评清单」模式，引导学生逐项自评后给路径——**不替学生下定论、不伪造数据**（自主性护栏）。
