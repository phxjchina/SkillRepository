# 七阶段指导手册（学生陪跑详细写法）

> 配套 `SKILL.md` §五。每个阶段给「目标 / 你的任务 / 教练怎么教 / 交付物 / 红线 / 闸门」。逆转自《计算机学院毕业设计审核手册》与往届高频雷区。

---

## 阶段 0 · 建档与倒排

**目标**：把毕业设计当成项目管，建立个人进度卡 + 倒排时间表。
**你的任务**：
- 列出学校关键节点与截止日（选题/任务书/开题/中期/初稿/定稿/答辩），倒推出每周该到哪。
- 建一个材料归档文件夹，按 `任务书/开题报告/过程材料/论文/答辩` 分好。
**教练怎么教**：给你一份倒排模板（第1周选题→第3周任务书→第6周开题→第7-13周实施→第14周中期→第15-18周论文→第19周答辩），并帮你把任务书进度表拆成周度 WBS。
**交付物**：个人进度卡（`coach_state.json`）+ 倒排表 + 归档文件夹。
**红线**：不建档=盲飞，后期必乱。
**闸门**：进度卡建好、截止日对齐学院通知。

## 阶段 1 · 选题

**目标**：拿到一个"做得完、有价值、说得清"的题目。
**你的任务**：写一份选题说明（题目 + 来源 + 意义 + 初步内容 + 技术路线 + 工作量自评）。
**教练怎么教（题目体检四问）**：
1. **可行性**：本科能力 + 设备/数据/环境可获取？别选需要你这学期学不会的深理论。
2. **工作量**：一学期做得完？太大（"智能制造全流程系统"）→ 缩；太小（"一个按钮"）→ 扩。
3. **价值**：解决什么具体问题？避免"为技术而技术"。
4. **规范**：名词准确无歧义，体现技术方法。
**题目句式模板**：
- 工程实现类：「基于<技术>的<对象><系统/平台>设计与实现」（如"基于STM32的嵌入式物联网通用实验平台的设计与实现"）
- 方法研究类：「<对象>的<方法>研究与实现」
- 避免单独用"研究""分析"等空泛词；题目含具体技术/对象。
**红线**：题目太大做不完、或太虚无对象、或与专业培养脱节。
**闸门**：题目被教师确认（进系统）。

## 阶段 2 · 配合任务书（任务书由教师填，你准备输入）

**目标**：让教师能基于你的要点写出一份合格任务书。
**你的任务**：向教师提交四份要点草稿。
**教练怎么教**：
- **①课题目标及要求**：拆成**可验收的功能/性能/技术指标**（如"实现XX控制，响应时间≤X ms"），别一句话了事、别与"主要内容"重复堆砌。
- **②主要内容及成果形式**：列 3-5 条核心工作；成果写「XX系统一套，毕业设计论文一份」，**禁用"系统说明书"**。
- **③进度安排 6 阶段**：时间连续无空档，终点=答辩日（如 2022-12-14~2023-05-28，以当年通知为准）。
- **④建议参考文献 ≥5篇/近3年为主/≥1外文**，GB/T 7714 著录、与课题**强相关**（别混入无关消费电子文献如 Samsung SmartThings）。
**文献著录红线**（GB/T 7714—2015，往届高频错）：
- 作者 ≤3 位全列，>3 位列前3位后加「,等」。
- 外文：作者. 题名[J]. 刊名, 年, 卷(期): 起止页. ——**卷后须有期号**，**页码不得重复**（`1437:012125-012125` 错，应 `1437(1):012125`），冒号前不留空格，刊名斜体。
- 封面"设计（论文）起止时间"连接符与进度表统一（"至"/"~"择一），数字与汉字间不加空格（`2021年12月24日至2022年6月8日`）。
- 一级标题编号与标题间空格全文统一。
**交付物**：任务书要点草稿（交给教师）。
**闸门**：教师正式下发任务书 + 三方手写签名。

## 阶段 3 · 开题报告（写附件5 + 开题PPT）

**目标**：说清"做什么、为什么做、怎么做"，通过开题答辩。
**固定章节**：`1 研究目的及意义`(1.1目的/1.2意义) · `2 国内外研究现状`(2.1国外/2.2国内) · `3 本课题要研究或解决的问题和拟采用的研究手段`(3.1内容/3.2问题/3.3手段) · `4 工作进度安排` · `参考文献`。
**教练怎么教**：
- **第3部分篇幅 > 第1+2部分之和**（最常见扣分项）；全文≥2000字。这是评委看"你到底想清楚没"的地方。
- **现状综述要有"评述"**：不只列"A做了X、B做了Y"，要加"然而现有工作在Z上不足，本文从W切入"。没评述=堆砌。
- **第4部分进度 = 任务书6阶段时间逐条一致**。⚠️ 判"空白"前必须看本地 `.docx` 原件——进度表在表格里，纯文本提取会丢。
- **参考文献 ≥10篇 / ≥2外文 / 80%近3年 / 须含任务书文献 / 去重**（同一文献不得重复编号）。
- 封面"完成时间"填阿拉伯数字，不得留空模板"20　　年　月　日"。
- 章节编号 `1 / 1.1 / 1.1.1`，题序与标题间空2格；图有图题（图1）置于图下方。
- **正文无残留模板提示文字**（如"(研究目的应该出现在这里…)"删净）；**全文通读校对无错别字漏字**（往届："客服"应为"克服"、漏"统"字）。
**开题PPT（12-14页）**：封面→目录→研究背景与意义→国内外现状(简)→研究内容→拟采用方法/技术路线→工作进度安排→预期成果。重点讲"你要做什么、怎么做"，别大段念文献。
**交付物**：开题报告（附件5）+ 开题PPT + 开题答辩记录。
**红线**：题目与任务书不一致、第3部分过短、进度与任务书不符、文献不达标、完成时间未填。
**闸门**：开题答辩通过（教研室+学院两级）。

## 阶段 4 · 工程实施（做任务书规定的系统/项目）

**目标**：做出任务书规定的主要功能，且留好论文素材。
**你的任务**：按计划实现系统，并持续留痕。
**教练怎么教**：
- **拆WBS**：把任务书"主要内容"拆成模块/周任务，画功能结构图 + 技术路线图（这俩图直接进开题/论文）。
- **技术选型答疑**：帮权衡 STM32/物联网/Web/Python/Java 等；给学习路径与避坑（如 MQTT vs NB-IoT 选型、前后端框架）。
- **留痕（最关键）**：每步截图、关键代码段、测试记录、运行日志、参数表——这些是论文第4-5章的素材。**没留痕=论文没东西写**，后期补图会被判造假。
- **防拖延**：周度对账进度表；落后超1周预警；落后超2周给"缩范围保核心"诊断（砍非核心功能，保任务书主功能）。
- **工作记录（周报）**：一周2次、内容具体（指导方式/日期/咨询问题/指导内容），体现师生互动。
**交付物**：可运行系统 + 设计文档 + 工作记录。
**红线**：系统偏离任务书主要功能、零留痕、长期零进展。
**闸门**：系统达任务书主要功能≥2/3、有完整留痕。

## 阶段 5 · 中期检查

**目标**：向教师/学院证明"进度正常、能按时完成"。
**你的任务**：写进度汇报。
**教练怎么教**：
- 做**进度对账表**（计划 vs 实际）：已完成/进行中/未开始 + 风险 + 改进措施。
- 落后超2周：诊断"缩范围保核心"，写明砍了什么、保了什么，让教师知情。
- 别写空话（"进展顺利"），写具体模块完成度百分比。
**交付物**：中期检查表 / 进度汇报。
**闸门**：中期通过（教学院长审）。

## 阶段 6 · 论文撰写（初稿 → 终稿）

**目标**：写出结构规范、本人工作量充足、格式合规的论文。
**逐章章法**：
- **摘要**：含目的/内容/方法/成果/结论五要素，≤500字，**不能写成心得体会**；中英文摘要第一段不缩进、其余缩进2字符、行距20磅。
- **目录**：与正文标题逐条一致；页码目录罗马数字、正文阿拉伯从1始；**章号连续无错乱**（测试章须为第5章而非第4章；TOC与正文编号一致）。
- **正文**：每章另起页；章3号/节4号/条款小4号；中文宋体、数字字母 Times New Roman；首行缩进2字符、行距20磅。
- **图表公式**：图号图名在图下居中（图1-1）；表三线表、表序在表上（表1-1）；公式居中带章内序号置右。
- **本人设计与实现 ≥ 全文 2/3**（非常重要），且覆盖任务书主要功能。
- **参考文献 ≥15篇 / ≥2外文 / 80%近3年 / 须含开题文献**，正文内有标注；序号左顶格加方括号。
- **结论**精炼、不写心得；**致谢**末有学生署名且含封面指导教师姓名。
**高频雷区**：摘要写心得、目录章号错乱、图号重复、英文术语前后不一致（OpenGL/valve 混用）、中文摘要被英文占据。
**交付物**：论文初稿 → 按教师/自检意见改 → 定稿。
**红线**：本人实现<2/3、文不对题、目录/格式混乱、文献不达标、抄袭。
**闸门**：查重达标 + 教师审核通过（进评阅/答辩）。

---

## 阶段 7 · 答辩准备

**目标**：用15分钟讲清工作，从容答问，通过答辩。
**你的任务**：做答辩PPT + 讲稿 + 模拟问答。
**教练怎么教**：
- **PPT结构（12-14页）**：封面→目录→研究背景与意义→国内外现状(1页)→研究内容→方法与技术路线→系统/项目实现(重点,多图)→测试与结果→总结与展望→致谢→答辩问答准备。
- **讲稿**：10–15分钟，练到脱稿；叙事线"背景→问题→我的工作→怎么做→结果→价值"。
- **模拟评委问答**：按 `references/答辩问答库.md` 出10道并给应答要点。
- **临场技巧**：严格控制时间；遇不会的题说"这方面我后续会补充"，别硬编；PPT图表清晰不堆字；着装与礼貌。
**交付物**：答辩PPT + 讲稿。
**闸门**：答辩通过、资料袋归档。

## 附：跨文档五条铁律（学生端提前对齐）

| 铁律 | 学生怎么做才不踩 |
|---|---|
| ①题目一致 | 任务书/开题/论文/答辩表题目一字不差（含"柜"等字别漏） |
| ②进度一致 | 开题第4部分进度 = 任务书6阶段时间 |
| ③文献递进 | 开题文献⊇任务书文献；论文文献⊇开题文献 |
| ④工具一致 | 任务书"使用工具"=开题"研究手段"=论文实际技术，别中途换 |
| ⑤工作量 | 论文本人实现≥2/3，覆盖任务书主要功能 |

## 附：论文写作规范速查（2025 届教师批改共性问题提炼 · 全文通用）

> 来源：`…\2025届毕业设计\毕业设计中期稿-第一次修改互评\毕业论文共性问题总结.docx`（彭老师批改原话）。写第 3-6 章前通读一遍，比写完返工省一周。

**需求分析章（第3章）**
- 章节叫"XX需求"，不叫"XX需求分析"；需求阶段禁止出现"模块"一词（模块是设计阶段概念）。

**相关技术章（第2章）**
- 只写"本设计用了它的什么特性、为什么选它"；百科式科普（开发板介绍/服务器介绍）全删。

**设计实现章（第4章）**
- 有"总体架构设计"字样必配**本论文特定领域**的总体架构图（抽象通用图无效）。
- 删操作手册式内容（"先点击…后部署…"）；界面/效果展示统一放测试章。
- 长内容用小标题分段或列表总结，保持层次；表格之后写"解释"（字段用处/约束/取值范围），不是"介绍"。

**图表规范（批量扣分重灾区）**
- 图表编号按章连续（图4-1…），图题置图下方、表题置表上方；三线表。
- 图所在段落去掉"首行缩进两字符"才能真正居中；全套图统一字体/箭头/形状风格。
- 图中文字要能在 100% 比例看清（建议华文中宋加粗、字占满形状、连线间距收紧）；深色截图调亮再贴（考虑打印）。
- 流程图用规范符号（起止圆角/判断菱形/流程矩形），别随手画框。

**行文**
- 中文宋体、英文 Times New Roman；同一缩写首次出现解释一次，全文统一。
- 语句通顺无错别字（历届有"客服/克服"这类错别字进终稿）。

**AIGC 红线**
- AI 可帮列提纲/改语病，**正文必须自己写**——2025 届有中期稿因 AI 生成痕迹被整段打回（教师原话"先把AI生成部分去掉再说"），查重+AIGC 检测是双红线。
