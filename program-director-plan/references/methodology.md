# 培养方案 OBE 反向设计方法论（专业负责人用）

本文件是 `program-director-plan` skill 的核心方法论，供设计本科专业培养方案与知识架构大图时参照。

## 1. 顶层设计原则

- **应用型定位**：与 C9/985/211 错位竞争，培养"能干活的人"，而非追求理论深度。
- **OBE 反向设计（Outcome-Based Education）**：以输出（毕业要求 / 目标系统）驱动输入（课程），自顶向下逐层分解。
- **专业定位"一句话"**：
  - 人工智能（AI）= 造聪明软件
  - 智能科学与技术（智科）= 构造智能系统（软硬协同）
  - 计算机科学与技术（计科）= 造计算机本身与底层硬件

## 2. 五列分解（系统 → 子系统 → 能力 → 知识点 → 课程）

| 列 | 含义 | 编号示例 | 说明 |
|----|------|----------|------|
| 1 系统 System | 专业要培养学生造出的"目标系统"大类 | S1 / Z1 / J1 | 专业顶层设计单元 |
| 2 子系统 Subsystem | 系统的下一级拆分 | S1.1 | 可独立工程实现 |
| 3 功能/能力 Capability | 子系统要具备的能力点 | S1.1.1 | 可考核的能力 |
| 4 知识点 Knowledge | 支撑能力点的知识点 | S1.1.1.1 | 教学最小单元 |
| 5 课程 Course | 由知识点映射而来的课程/教材章节 | §章节号 | 可溯源 |

- 课程列由知识点映射，标注 §教材章节号以便溯源。
- 箭头方向：系统 → 子系统 → 能力 → 知识点 → 课程，表示"分解"与"支撑/映射"。

## 3. 层级编号规则

- **系统** = `S1` / `Z1` / `J1`（前缀：S=人工智能，Z=智能科学与技术，J=计算机科学与技术）
- **子系统** = `S1.1`
- **能力（功能）** = `S1.1.1`
- **知识点** = `S1.1.1.1`
- 右侧课程即由该知识点映射而来

> 编号本身即表达隶属关系，便于在大图与文档中精确定位、互相引用。

## 4. 能力基座与子能力链（四层体系）

**能力基座 → 子能力链（每链配锚项目）→ 系统综合 → 平台产出（竞赛/科研/毕设/就业）**

- 智科四种子能力 `B1–B4`：信息系统开发 / 嵌入式开发 / 信息物理融合 / AI 算法模型（B = Base 能力基座）。
- 每类目标系统由若干子能力组合支撑；每条子能力链绑定一个**锚项目**（真实工程项目），作为"学完即用"的载体。
- 平台产出接入"课程实验—学科竞赛—教师科研—毕业设计"四位一体平台。

## 5. 同题异构 PjBL（跨专业协同）

- 一次实践、三方获益：**AI 出算法、智科出系统、计科出底层载体**。
- 跨专业依赖总图（`reverse_cross.svg`）用箭头（如 22 条）证明能力闭环（边缘部署、视觉检测、雷达信号处理等）。
- 含义：多专业并非孤立，而是形成协同育人生态，可作为学位点建设的底座。

## 6. 工程教育认证支撑矩阵

- 将"课程—能力—毕业要求指标点"对应成表。
- 对接工程教育专业认证（中国工程教育专业认证协会）2024 版标准，核心参考其指标体系（表 4-1~4-4）。
- 该矩阵是培养方案合规性的关键证据。

## 7. 知识架构大图（SVG）绘制规范

- 五列按 x 坐标分列：**系统(120) / 子系统(334) / 功能能力(548) / 知识点(764) / 课程(978)**（详见 skill 的 `assets/knowledge-architecture-template.svg`）。
- 系统框内写"编号 + 名称"；用箭头连线表达分解与映射。
- 导出 `reverse_<专业>.svg`；跨专业导出 `reverse_cross.svg`。
- 图例、列标题、锚项目标记需齐备，保证读图自明。

## 8. 产出物结构（文档）

- **三文档（必备）**：培养方案说明 + 知识点说明 + 大图说明
- **可选增强**：领导汇报稿（照读版，约 12–15 分钟）、全术语详解与"为何这么画"、逐线分解详解、知识点内在联系详解、合并编号版
- **公文风规范**：
  - 标题用黑体（SimHei），正文用宋体（SimSun）
  - 正文首行缩进 2 中文字符（`w:firstLineChars=200`）
  - 左侧导航结构图：各级标题套 Heading 1/2/3 样式，且"文档结构导览"目录区须重置为 Normal，避免导航重复
  - 文档须可独立读懂，不依赖支撑材料（见第 9 节）

## 9. 自解释原则（关键）

- 文档可独立读懂，不依赖支撑材料。
- 字母数字标记（`SYS-` / `B-` / `S/Z/J` 编号、`reverse_*.svg` 文件名）首次出现须给出中文全称与含义对照表（如 2.4.1 术语对照小节）。
- 占位符 / 无出处的编号（如"0810"）不得出现。
- 无法核实的量化数字（如"9 个实践基地"）改用自解释措辞（如"已共建的校企联合实验室与实践基地（即与行业企业联合建立、承接真实课题与毕业设计的产教融合平台）"）。
- 缩写首次出现须展开（如 AIMA = Artificial Intelligence: A Modern Approach《人工智能：现代方法》；PjBL = Project-Based Learning 项目式学习）。

## 10. 从培养方案 → 学位点培育建设方案

将三专业产物（知识架构大图、课程清单、教材体系、锚项目、竞赛矩阵、本科毕业生基础）作为学科建设基础，按"申请基本条件对标 → 差距分析 → 建设目标 → 任务举措 → 经费 → 分年度计划"组织，充实进学位点培育建设方案（详见 `dept-head-review` skill 的 `references/rollup-degree-plan.md`）。
